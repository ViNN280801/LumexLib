# Правила udev для доступа к приборам Lumex без root

На Linux узлы `/dev/ttyUSBN`, `/dev/ttyACMN` и `/dev/hidrawN` по умолчанию
доступны только root и группе, которая ими владеет. Если у пользователя нет
доступа, открытие порта в `lumex::transport` заканчивается ошибкой
`transport_errc::permission_denied`, а в журнале (компонент `transport.serial`,
уровень `error`) появляется сообщение с узлом, его владельцем, группой, режимом
в восьмеричном виде и подсказкой, как исправить. Если у группы узла нет
чтения и записи, подсказка предлагает только правило udev: вступление в такую
группу не поможет.

В каталоге два файла, это два способа выдать доступ (достаточно одного):

| Файл | Кому дает доступ |
| --- | --- |
| [`99-lumex-serial.rules`](99-lumex-serial.rules) | группе узла: `dialout` для `ttyUSB*` и `ttyACM*`, `plugdev` для `hidraw*`; пользователь должен в группу входить |
| [`70-lumex-uaccess.rules`](70-lumex-uaccess.rules) | пользователю активного локального сеанса, членство в группе не нужно |

В собранном пакете оба файла лежат в `share/LumexLib/udev` (в префиксе
установки); в дереве исходников это `lumex/examples/transport/udev`.

Строки обоих файлов выбирают устройства по идентификатору производителя USB
`16e0`. Для переходника USB-COM другого производителя нужна своя строка (раздел
«Другой переходник»).

## Правило для группы

Файл `99-lumex-serial.rules` выдает группе чтение и запись на узлы приборов:

| Узел | Группа | Режим |
| --- | --- | --- |
| `ttyUSB*`, `ttyACM*` | `dialout` | `0660` |
| `hidraw*` | `plugdev` | `0660` |

Остальным пользователям доступа нет: режим `0664` дал бы любому пользователю
системы открыть узел на чтение и забирать данные прибора, а библиотеке все
равно нужны чтение и запись.

Установка:

```sh
sudo cp 99-lumex-serial.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

После этого отключите прибор и подключите снова, если права на уже
существующий узел не изменились.

## Правило без группы: uaccess

Файл `70-lumex-uaccess.rules` ставит узлам тег `uaccess`: systemd-logind
добавляет в ACL узла пользователя, который сидит за рабочим местом (графический
или консольный вход). Вступать в группу и выходить из сеанса не нужно.

```sh
sudo cp 70-lumex-uaccess.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

Номер файла меньше 73 не случайно: тег `uaccess` обрабатывает
`73-seat-late.rules`, и правило с номером 73 и выше срабатывает слишком поздно,
доступ не появится. Для сеанса без рабочего места (ssh, служба) тег не
помогает, там нужно правило для группы. Установить можно оба файла сразу.

## Другой переходник

Строки правил выбирают устройство по `ATTRS{idVendor}=="16e0"`. Переходник
другого производителя (FTDI, CP210x, CH340) этому условию не отвечает, поэтому
правило ему доступа не выдаст. Идентификаторы читаются у подключенного
устройства:

```sh
udevadm info -a -n /dev/ttyUSB0
```

В выводе нужны строки `ATTRS{idVendor}` и `ATTRS{idProduct}` ближайшего
родителя типа `usb` (у переходника FTDI это, например, `0403` и `6001`). Для
этого переходника добавьте строку в свою копию файла:

```text
SUBSYSTEM=="tty", KERNEL=="ttyUSB[0-9]*", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", MODE="0660", GROUP="dialout"
```

В файле `70-lumex-uaccess.rules` строка та же, но вместо `MODE` и `GROUP`
стоит `TAG+="uaccess"`. После правки повторите `udevadm control --reload-rules`
и `udevadm trigger`. Не ставьте общее условие без `idVendor` и `idProduct`:
оно выдаст доступ ко всем последовательным портам системы.

## Группа вместо правила

Правило для группы дает доступ группе, поэтому пользователь должен в нее
входить. Если правило не ставится, достаточно добавить пользователя в группу,
которой принадлежит узел (для `ttyUSB` и `ttyACM` обычно `dialout`, для
`hidraw` `plugdev`):

```sh
sudo usermod -aG dialout "$USER"
sudo usermod -aG plugdev "$USER"
```

Изменение группы вступает в силу после нового входа в систему: выйдите из
сеанса и войдите снова. Чтобы проверить, не выходя, `newgrp dialout` запускает
в текущем терминале новую оболочку с этой группой; в других окнах и в уже
запущенных программах группа не появится, а прибор нужно открывать из этой
оболочки. Проверить, что пользователь входит в группу, можно командой `id`.

## Проверка

```sh
ls -l /dev/ttyUSB0
```

Пример результата:

```text
crw-rw---- 1 root dialout 188, 0 окт 22 10:15 /dev/ttyUSB0
```

Здесь владелец `root`, группа `dialout`, режим `0660` (`crw-rw----`). Прибор
откроется у пользователя из группы `dialout`. Если группа не та или у группы
нет записи (например, режим `0600`), правило не сработало:
проверьте идентификатор производителя через `udevadm info -a -n /dev/ttyUSB0`
(строка `ATTRS{idVendor}`) и повторите `udevadm control --reload-rules` и
`udevadm trigger`. Для правила `uaccess` узел показывает ACL: `getfacl
/dev/ttyUSB0` перечисляет пользователя сеанса.

## Windows

На Windows этих файлов не требуется. Ошибка `ERROR_ACCESS_DENIED` при
открытии COM-порта означает, что порт занят другим процессом, поэтому
библиотека не превращает ее в `permission_denied`: она остается системной
ошибкой.
