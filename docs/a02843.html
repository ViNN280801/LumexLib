Detailed Description

template<std::size_t Alignment>
struct lumex::core::expected::result::detail::storage::has_val_flag< Alignment >

has_val of [expected.object.general]: a bool in a class as large as the alignment of the union before it.

A plain bool after a union of 4 bytes leaves 3 bytes of tail padding in the storage. The storage is a base class of expected (a chain of them), and the Itanium C++ ABI lets a derived class use the tail padding of a base that is not a POD, so the compiler may copy only the 5 bytes in front of the padding. GCC 13 then builds a trivially copyable expected<int, unsigned> that a function returns in one 8-byte register through a stack slot (a 4-byte store for the value, a 1-byte store for the flag, an 8-byte load that must wait for both: a store-forwarding stall, counter LD_BLOCKS.STORE_FORWARD, one per call chain). A data member always occupies its whole sizeof, so the padding that this class holds is not a base's tail padding, the storage has none, and the compiler keeps the object in the register as it does for the members of std::expected (which has no base classes). sizeof and the alignment of expected do not change: the size of a union is a multiple of its alignment, so sizeof (union) + alignment is also what the bool and its padding made.
