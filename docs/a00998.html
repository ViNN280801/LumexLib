Detailed Description

The enumerations assertion_kind, evaluation_semantic and detection_mode, and the class contract_violation that a violation handler receives.

The names, the enumerator values and the accessors follow <contracts> of the C++26 draft ([support.contract], P2900): assertion_kind (pre 1, post 2, assert 3), evaluation_semantic (ignore 1, observe 2, enforce 3, quick_enforce 4) and detection_mode (predicate_false 1, evaluation_exception 2), and contract_violation with comment, detection_mode, is_terminating, kind, location and semantic. The types are the module's own on every standard and toolchain, not aliases of the standard ones (no library ships <contracts> yet). Differences from the standard class: it is a plain value that can be constructed (the macros of this library create it) and copied, and its location is the module's source_location. Only assertion_kind::assert is produced by LUMEX_CONTRACT_ASSERT; pre and post exist so that a violation reported by the compiler's own contracts converts into the same class.

A contract_violation converts from any object that has the six accessors of the standard class (the std::contracts::contract_violation of a C++26 library, or another type of that shape) through an explicit template constructor: the strings and the location are taken by value, so the result does not depend on the lifetime of the source.
