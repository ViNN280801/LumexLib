Detailed Description

Constants, the byte type and the traits behind span.

Holds everything that span and the free functions around it share: dynamic_extent, byte (an own scoped enumeration with the operators of std::byte, in every standard), the customization trait is_contiguous_iterator and the detection traits of the C++11 stand-ins for the concepts the C++20 std::span constrains its constructors with (contiguous_range, sized_range, borrowed_range, contiguous_iterator, sized_sentinel_for). The header also defines the configuration macros LUMEX_SPAN_HAS_CONCEPTS and LUMEX_SPAN_HAS_RANGES. Nothing here allocates or throws.

Macro Definition Documentation

◆ LUMEX_SPAN_HAS_CONCEPTS

#define LUMEX_SPAN_HAS_CONCEPTS   0

1 when the C++20 iterator concepts (std::contiguous_iterator, std::sized_sentinel_for) are available, 0 otherwise.

Tested on the library feature (__cpp_lib_concepts) together with the language one, not on __cplusplus alone: GCC 8 accepts -std=c++2a without concepts.

◆ LUMEX_SPAN_HAS_RANGES

#define LUMEX_SPAN_HAS_RANGES   0

1 when std::ranges::enable_borrowed_range and std::ranges::enable_view exist, 0 otherwise.

When it is 1, span opts into both and accepts the rvalues of every standard borrowed range (for example std::span) in its range constructor.

◆ LUMEX_SPAN_HAS_STD_SPAN

#define LUMEX_SPAN_HAS_STD_SPAN   0

1 when std::span and std::byte both exist (C++20 with <span>), 0 otherwise.

When it is 1, span converts to and from a std::span of the other byte type (byte and std::byte).

◆ LUMEX_SPAN_MAY_ALIAS

#define LUMEX_SPAN_MAY_ALIAS

Marks the own byte as a type that may alias any object, as the standard allows std::byte to.

GCC and Clang do not treat a scoped enumeration with an unsigned char base as a character type, so without the attribute a write through a span<byte> is not seen by a read of the viewed object.
