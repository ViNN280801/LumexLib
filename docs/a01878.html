Detailed Description

template<class T, class Allocator = std::allocator<T>>
class lumex::core::circular_buffer::circular_buffer< T, Allocator >

Circular buffer with a run-time capacity that overwrites when full (similar to Boost's circular_buffer).

Template Parameters
TElement type stored in the buffer.
AllocatorAllocator type; default std::allocator<T>.

This container mimics the main behavior of Boost circular_buffer while staying C++11 and header-only. The capacity is set at construction (or by set_capacity, rset_capacity, resize and assign) and may be 0: a buffer with capacity 0 is valid, holds nothing and ignores push_*.

Note
Brace initialization with one integer is a list, as for std::vector: circular_buffer<int> b{16}; has capacity 1 and holds 16, and circular_buffer<int> b = {5, 3}; has capacity 2 and holds 5 and 3. Use parentheses for a capacity: circular_buffer<int> b (16);.

Characteristics

  • Insert into a full buffer overwrites the oldest element.
  • T need not be default-constructible (elements are created on demand).
  • Strong exception safety for insert on a non-full buffer and, when T is move-constructible, for the construction part of an overwrite (see below).
  • Random access at indexes (0..size()-1), where 0 is the oldest element.
  • emplace_back / emplace_front need room for the new element and throw std::length_error on a buffer with capacity 0 (they return a reference); push_back / push_front ignore their argument then.
  • Not thread-safe.

Guarantees, invalidation, and complexity

Pointer/iterator/reference invalidation

Iterators store a logical index, so any operation that moves the head remaps "logical index -> object". Those operations invalidate every iterator. The objects themselves do not move.

Per operation:

  • emplace_back / push_back on a non-full buffer:
    • iterators: remain valid (except end(), which changes);
    • references/pointers to existing elements: remain valid.
  • emplace_front / push_front on a non-full buffer:
    • iterators: all invalidated (head changes, logical indexes shift);
    • references/pointers: remain valid (objects do not move).
  • emplace_back / push_back on a full buffer (overwrite the oldest):
    • iterators: all invalidated (head changes);
    • references/pointers: the destroyed front element is invalid; the rest stay valid.
  • emplace_front / push_front on a full buffer (overwrite the newest):
    • iterators: all invalidated (head changes);
    • references/pointers: the destroyed back element is invalid; the rest stay valid.
  • pop_front:
    • iterators: all invalidated (head changes);
    • references/pointers: the removed element is invalid; the rest stay valid.
  • pop_back:
    • iterators: iterators to the last element and end() are invalidated; the rest stay valid;
    • references/pointers: the removed element is invalid; the rest stay valid.
  • insert, erase, erase_begin, erase_end, resize: every iterator is invalidated; elements are moved by assignment, so references and pointers to the elements that stay are valid but refer to other values.
  • set_capacity, rset_capacity, linearize (when it has to move elements), assign: every iterator, reference and pointer is invalidated.
  • clear:
    • iterators/references/pointers: all invalidated.
  • swap:
    • iterators: all invalidated (they are bound to this container object);
    • references/pointers: still point at the same objects, now owned by the other buffer.

Complexity

Core operations are O(1): indexed access, front/back, push_*/emplace_*/pop_*, including overwrite. Iteration is O(n). swap is O(1). Copy, assign, set_capacity, rset_capacity, resize, insert and erase are linear.

Exception guarantees

  • Construct/insert on a non-full buffer: strong guarantee (commit-or-rollback).
  • Overwrite (full buffer): the new element is first built in a temporary, so when its construction throws the buffer is unchanged. Then the replaced element is destroyed and the new one is moved (or, for a T without a move constructor, copied) from the temporary into its place; if that throws the buffer stays consistent and holds one element fewer (basic). Only for a T that is neither move- nor copy-constructible is the replaced element destroyed first and the new one constructed in place (basic, and the arguments must not refer to the replaced element).
  • Copy construction and copy assignment: strong (nothing leaks, *this is unchanged when a copy throws).
  • set_capacity, rset_capacity, linearize, assign: strong.
  • insert, erase, resize: basic (the buffer stays valid); resize and insert roll back the elements they constructed when a construction throws.
  • pop_*, clear, swap do not throw (as declared noexcept/macros).

Thread safety

The container is not thread-safe. Concurrent access from several threads needs external synchronization.

Iterators

Iterators are random-access (they model std::random_access_iterator from C++20). Because they store an index, any change of head makes them inconsistent with the original elements (see invalidation). iterator converts to const_iterator and the two compare with each other.

Memory contiguity

The container does not promise contiguous T like std::vector; linearize makes the content contiguous in the storage and returns a pointer to it, is_linearized tells whether it already is. There is no data(). Addresses of live elements stay stable across operations that do not destroy that element; overwrite/erase invalidates the address.

Comparison

  • ==, !=, <, <=, >, >= are lexicographical on the logical sequence; they require the matching operations on T.
  • Operator <=> is available in C++20+ for any T that is std::three_way_comparable; it returns std::compare_three_way_result_t<T> (strong for int, partial for double).

Allocator, copy, move and swap

Copy construction uses std::allocator_traits<Allocator>::select_on_container_copy_construction. Copy assignment follows std::allocator_traits<Allocator>::propagate_on_container_copy_assignment: when it is true the allocator of the source is taken (the old storage is released with the old allocator); otherwise the own allocator is kept and the new storage is made with it. The move operations always move the allocator along with the storage (propagate_on_container_move_assignment is not consulted). On swap, allocators are exchanged only if std::allocator_traits<Allocator>::propagate_on_container_swap::value is true. Otherwise they are assumed equivalent (as for the standard containers; a debug build asserts it); elements do not move.

inlinenoexcept

Exchanges the contents of two buffers.

Swaps every element between this buffer and other. If std::allocator_traits<Allocator>::propagate_on_container_swap::value is true, allocators are swapped too. Otherwise allocators are not swapped, and they are assumed equivalent (undefined behavior otherwise, as for the standard containers; a debug build asserts it).

Note
Invalidates every iterator (they are bound to this container). References/pointers stay valid, but ownership moves to the other buffer.
Complexity: O(1).
Exceptions
Doesnot throw when the declared noexcept conditions hold.
Parameters
otherBuffer to swap with.
Note
This function is noexcept under allocator-dependent conditions.
