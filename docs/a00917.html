Detailed Description

Internal helpers of expected: language helpers that C++11 lacks as constexpr (fwd, mv, address_of, construct_at, destroy_at), the constraints of the monadic operations, the traits behind the converting constructors and the comparisons, and invoke_call, the standard INVOKE for C++11.

Everything here lives in lumex::core::expected::result::detail and is not an interface for consumers. The header exists so that the primary template and the void specialization of expected (and their storage in ExpectedStorage.hpp) share one definition of each rule instead of repeating it in every overload. It builds on Unexpected.hpp (the traits of the error side) and only forward declares expected, so it is included by Expected.hpp, ExpectedVoid.hpp and ExpectedStorage.hpp. It also defines LUMEX_EXPECTED_CONSTEXPR_CXX20, the specifier of the members that change the active alternative of the union.

◆ LUMEX_EXPECTED_CONSTEXPR_CXX20

#define LUMEX_EXPECTED_CONSTEXPR_CXX20

constexpr where the language lets a constant expression start the lifetime of an object in a union (std::construct_at on an inactive member, P0784, P1330) and contain a try block (P1002): C++20 with a constexpr of 201907L and std::construct_at; empty before.

The members that change the active alternative of expected (construction from another expected, a non-trivial copy or move, assignment, emplace, swap) and the non-trivial destructor are marked with it; the observers, the converting and value constructors and the comparisons are constexpr from C++11 (see the class comment of expected).

◆ LUMEX_EXPECTED_HAS_EXCEPTIONS

#define LUMEX_EXPECTED_HAS_EXCEPTIONS   LUMEX_EXPECTED_COMPILER_HAS_EXCEPTIONS

1 when value () of an expected that holds an error throws bad_expected_access, 0 when it calls std::terminate.

The default follows the compiler (see LUMEX_EXPECTED_COMPILER_HAS_EXCEPTIONS): 0 with -fno-exceptions (or MSVC without /EHsc), 1 otherwise. A program may define the macro as 0 before the first include of the library to get the terminating value () with exceptions on; nothing else changes (emplace, assignment and swap keep their strong guarantee). Every translation unit of one program must see the same value (the functions are inline; MSVC reports a mismatch at link time through detect_mismatch, GCC and Clang do not detect it).
